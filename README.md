# COMP3850 PACE Group 54

This project explores a membership inference attack (MIA) against a record linkage model. The goal is to evaluate whether an attacker can infer whether a record pair was part of a model's training data, and to measure how different shadow-model configurations affect attack effectiveness.

## Project overview

The repository is built around a Python pipeline that:
- loads and validates embedding data,
- trains shadow and target linkage models,
- extracts membership-related signals such as confidence, loss, and margin,
- evaluates attack performance across multiple shadow-model setups,
- saves results and plots for analysis.

## Required local data

The embedding data for this project was provided to the team and is not published online. Before you can run the pipeline on your own machine, you must place the provided dataset into the repository directory.

Create a folder named `Embeddings/` in the project root and drag in the supplied `.npy` files. The scripts expect files such as:

- `Embeddings/x1_target_train.npy`
- `Embeddings/x2_target_train.npy`
- `Embeddings/y_target_train.npy`
- `Embeddings/x1_target_test.npy`
- `Embeddings/x2_target_test.npy`
- `Embeddings/y_target_test.npy`
- `Embeddings/x1_shadow_train.npy`
- `Embeddings/x2_shadow_train.npy`
- `Embeddings/y_shadow_train.npy`
- `Embeddings/x1_shadow_test.npy`
- `Embeddings/x2_shadow_test.npy`
- `Embeddings/y_shadow_test.npy`

If these files are missing, the pipeline will fail when it tries to load them.

## Running the pipeline

### 1. Prepare the environment

From the repository root, create and activate a virtual environment if needed, then install the project dependencies:

```bash
python -m venv .venv
source .venv/bin/activate   # Linux/macOS
# or .venv\Scripts\activate  # Windows
pip install numpy pandas scipy scikit-learn tensorflow matplotlib
```

### 2. Validate the data

Before running the full attack pipeline, you can quickly check the dataset integrity and shapes:

```bash
python check_data.py
```

This script verifies that the arrays are present and finite, and prints the train/test shapes for the target and shadow datasets.

### 3. Generate the findings

Run the end-to-end membership inference pipeline:

```bash
python run_mia_attack.py
```

This process will:
- train the target linkage model,
- generate K=10 shadow subsets and train shadow models,
- compute statistical differences in attack features,
- train attack classifiers for K = 1, 5, and 10,
- evaluate the attack on the target model,
- save all outputs to the `results/` directory.

The script may take some time to complete because it trains TensorFlow models and evaluates several attack configurations.

## Viewing the generated results and findings

Once the pipeline completes, open the `results/` folder in the repository root. This folder contains the evidence generated by the attack experiment.

### CSV summaries

The following CSV files are generated:

- `results/shadow_models_training_log.csv` — per-shadow-model training accuracy, F1, and runtime.
- `results/feature_distribution_stats.csv` — mean/std statistics for membership features (confidence, loss, margin, entropy).
- `results/shadow_k_sensitivity_analysis.csv` — attack performance across K = 1, 5, and 10 shadow models.

These can be opened in Excel, Google Sheets, VS Code, or any spreadsheet viewer.

### Text findings

The pipeline also writes a human-readable summary to:

- `results/target_attack_results.txt`

Open it in a text editor or use a terminal command such as:

```bash
cat results/target_attack_results.txt
```

This file contains the final attack metrics and the confusion matrix summary for the target model.

### Plots and visual findings

The repository saves these figures in `results/`:

- `results/multi_k_shadow_roc_comparison.png` — ROC curves for K = 1, 5, and 10.
- `results/feature_distribution_comparison.png` — distribution of confidence and loss for member vs non-member samples.
- `results/target_mia_confusion_matrix.png` — confusion matrix for the final target-model attack.

Open these files in any image viewer, browser preview, or GitHub file viewer to inspect the model behaviour visually.

## File structure and purpose

### `check_data.py`
Checks the integrity and shape of the training and testing embedding arrays. It prints dataset dimensions and label counts for both the target and shadow datasets, helping confirm that the data is valid before model training.

### `train_shadow.py`
Trains a single shadow linkage model using a Siamese autoencoder plus a classification head. It encodes record pairs into embeddings, compares their differences, and trains a binary linkage classifier.

### `train_multi_shadow.py`
Extends the single-shadow workflow into a multi-shadow training pipeline. It creates multiple shadow-model subsets, trains them independently, and extracts attack feature vectors for downstream membership inference evaluation.

### `test_k_subsets.py`
Defines the K-subset sampling logic used to partition the shadow dataset into multiple training/test subsets. This allows experimenters to test how the number of shadow models affects attack performance.

### `run_mia_attack.py`
Runs the end-to-end attack pipeline. It trains the target linkage model, builds shadow models, extracts attack signals, evaluates a membership inference classifier, and saves findings such as confusion matrices, ROC analysis, and CSV summaries.

### `results/`
Stores the generated evidence and evaluation outputs from the attack pipeline, including:
- CSV summaries of model metrics,
- feature distribution statistics,
- shadow-model sensitivity results,
- plots for ROC and confusion-matrix comparisons.

### `.gitignore`
Excludes local environment and generated data files such as virtual environments, caches, and large numpy arrays.

## Discussion of findings

The experimental findings are captured in the generated CSV summaries and plots inside the `results/` directory. The main outputs show how the attack performance changes as the number of shadow models increases, and whether member samples can be distinguished from non-member samples via confidence, loss, margin, and entropy signals.

To interpret the results:
- Higher ROC AUC and TPR@FPR values indicate stronger membership leakage.
- Large differences in feature distributions between member and non-member samples suggest the model leaks membership information.
- The confusion matrix and sensitivity tables show which attack settings are most effective against the target model.

If you want to reproduce or extend the analysis, rerun `python run_mia_attack.py` after placing the supplied embedding files into `Embeddings/` and ensuring the environment is set up.
